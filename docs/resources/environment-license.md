# Environment & License

<!-- NOTE: read-only platform management surface; license-settings has no describe form. -->

## Overview

Read-only view of the platform tenant itself: which environment the active context points at, whether it is a trial or a platform subscription, and which licensed feature settings are switched on. Use it to confirm you are talking to the environment you think you are, and to check whether a capability (Automation, AI functions, log ingest tiers) is licensed before building on it. Nothing here is writable — licensing changes happen in Account Management, not through dtctl.

## Output

All three are single-object (or flat-list) reads, so there are no IDs to resolve and no pagination.

- **`environment`** returns `environmentId`, `type`, `state`, `createTime`, and `blockTime`. The table form shows ID, type, and state; `describe` adds the two timestamps, date-only.
- **`license`** returns the two booleans `trial` and `platformSubscription`.
- **`license-settings`** returns a flat list of `{key, value}` objects, one per licensed feature. Note the mismatch: the table column is headed `ENABLED`, but in `-o json`/`-o yaml` the field is named **`value`** and its contents are the **string** `"true"`/`"false"`, not a boolean. Compare against `"true"`, not `true`.

`-o json` and `-o yaml` return the full object in every case; nothing is truncated in the table form except the date formatting noted above.

## Examples

```bash
# Which environment is this context actually pointing at?
dtctl get environment
```

```
ID         TYPE       STATE
abc12345   INTERNAL   ACTIVE
```

```bash
# Trial or paid?
dtctl get license
```

```
TRIAL   PLATFORM SUBSCRIPTION
false   true
```

```bash
# Full detail, including the creation and block timestamps
dtctl describe environment
```

```
ID:         abc12345
Type:       INTERNAL
State:      ACTIVE
Created:    2025-03-13
Block Time: 2031-01-01
```

```bash
# Is a specific capability licensed? Filter by one or more keys.
dtctl get license-settings AUTOMATION AI_FUNCTIONS_STANDARD
```

```
KEY                     ENABLED
AI_FUNCTIONS_STANDARD   true
AUTOMATION              true
```

```bash
# Gate a script on a licensed feature (note: the JSON field is a string)
dtctl get license-settings AUTOMATION -o json --jq '.[0].value'    # -> "true"
```

## Notes

- **`license-settings` has no `describe` form** — each object is just a key and a value, so `get` already shows everything.
- **An unknown key is not an error.** `dtctl get license-settings NOT_A_REAL_KEY` prints `No resources found.` and exits 0, so a script that greps for a key name should check the row count rather than the exit code.
- Both resources accept short aliases: `env` for `environment`, `license-setting` for `license-settings`.
- The required scope for all five commands is `app-engine:apps:run`, which most contexts already hold — see **[TOKEN_SCOPES.md](../TOKEN_SCOPES.md)**.
