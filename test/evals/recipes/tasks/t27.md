## Prompt

The `${EVAL_T2_DEEP_SERVICE}` service shows almost no failed requests over the
last 6 hours, yet users report errors from it. What is actually failing inside
it, how often, and why?

## Rubric

Ground truth: `requests` (root requests and root failures in 6h) and
`error_spans` (error spans by span name and kind, with distinct traces, HTTP
status code, URL and status message), measured at batch start and end.

- 3: identifies the main failure classes in `error_spans` (e.g. an outgoing
  call failing with a specific HTTP status for a specific resource, and LLM
  model errors if present) with counts in the right range (counting traces or
  span layers is fine if it says which) AND a concrete reason for each.
- 2: one failure class right with evidence, the other missing; or both
  classes named without reasons or counts.
- 1: reports only the low request failure rate plus a vague mention of
  "some errors".
- 0: concludes nothing is failing, or no answer.
